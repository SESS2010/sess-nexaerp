## The 216 rupee difference

The arithmetic was reported before changing expectations:

- Old: .30 x (4000 material + 720 recoverable GST + 12 freight) = 1419.60.
- Correct accepted component cost: .30 x (4000 + 12) = 1203.60: material 1200,
  freight 3.60. The excluded recoverable GST is .30 x 720 = 216.
- The retained .20 component is 800 material + 2.40 freight = 802.40.

The fixture explicitly selects FULLY_RECOVERABLE tax treatment. This accepted BOM cost
projection does not rewrite historical FIFO: the returned .10 restores the original
.10 x 4720 = 472 issue value; the FIFO report also carries 1.20 freight, for 473.20.
Immutable layer, replay and refusal checks remain.

## Additional concurrency defects and deterministic proof

- **Payment:** the inner database-function helper previously replaced SQLSTATE 40001 with
  a business exception and lost the original cause. Preserve the typed cause; prove
  rollback, explicit same-key retry and replay at both payment-function and
  command-receipt insertion boundaries, with no duplicate payment or allocation.
- **QC:** its endpoint flattened a typed concurrency exception, and the error envelope
  guessed the category from message words. Let the typed exception reach central handling
  and preserve its classification using a server-only context marker. Identical wording on
  an ordinary business exception stays `BUSINESS_RULE_CONFLICT`; a typed concurrency
  exception mentioning idempotency stays `CONCURRENCY_CONFLICT`.
- **GRN and opening stock:** use the existing SQLSTATE helper to unwrap EF save errors as
  well as direct PostgreSQL exceptions. Deterministic audit-insertion failures previously
  returned **500**; they now return **409**. A QC revision-insertion probe also exercises
  the real QC endpoint. Every probe preserves posting/movement/FIFO/audit counts and
  document status/version, with zero retained command registrations.

These probes run outside the measured simultaneous batch. The original eleven-user
workload and its actor, scope, rollback, retry and no-deadlock assertions remain.
**No automatic retry was added to the application. No production SQL or migration changed.**

### Frontend impact

The 409 envelope now carries `Type https://api.sess.example/problems/concurrency-conflict`,
`Title "Concurrency conflict"`, `Code CONCURRENCY_CONFLICT` for typed concurrency failures,
and GRN/opening-stock conflicts move from 500 to 409. Details and the remaining

## Recorded operating-system interruptions

The first Round 4 nightly invocation started at 19:44 on 22 September. Windows User32
event 1074 records a user-session power-off at 21:13:56, shutdown at 21:14:18 and boot at
21:15:12. No Workflow TRX resulted; Concurrency and Lifecycle had not started. A restart
at 21:59 was itself cut short with the machine while the Workflow gate was running, again
producing no TRX; because its wrapper died inside the `try`, the development nightly task
was left Disabled until 23 September.

Neither interruption is a pass or a test assertion failure. The interrupted directories
are retained as `2026-09-22-round4-poweroff-interrupted` and
`2026-09-22-round4-restart-aborted`. Focused, Debug and Release TRX predate the first
shutdown and remain valid for the identical candidate; all 884 hashes were rechecked
before each restart.

On 23 September the nightly task was verified against its saved definition — identical in
principal, trigger, action and settings, differing only by the injected
`<Enabled>false</Enabled>` — then re-enabled and recorded. Four orphan disposable clusters
left in TEMP by the interrupted runs (467 MB) were removed under a receipt. The completed
23 September run left **no orphan clusters**, which supports the diagnosis that the leak
appears when a run is killed rather than in normal operation. The resume-marker and
memory-guard fix is approved and scheduled after go-live:
[harness resilience proposal](harness-resilience-proposal.md).
