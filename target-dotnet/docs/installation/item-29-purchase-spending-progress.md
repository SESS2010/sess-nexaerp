GET /api/v1/dashboards/purchase/spending returns accepted purchases less reversals. Material value and allocated charges are separately visible; Amount is their sum. This follows the established vendor-purchase report's decision-event basis. It is not a bank-cash measure or the value of issued PO commitments. Currencies are kept separate with no conversion.

The response contains current month, quarter and April–March financial year summaries; financial-year top ten vendors per currency; financial-year category totals; twelve monthly buckets; and filtered, paged bill-event rows. Category uses the receipt's recorded category ID/code, not the item's current category. PO counts are distinct root POs with activity in the period. Bill counts are distinct bills with activity. An acceptance and reversal of the same bill both appear, with opposite signs; a fully reversed bill can still count as activity while its net value is zero.

Filters affect the detailed rows and TotalRows, not the overview summaries. Each summary is clickable by choosing period=month, quarter or financial-year. The trend uses period=month&month=YYYY-MM-01. Vendor/category breakdowns use vendorId/categoryId plus currency, with financial-year as the default period. BillId shows that bill's events in the chosen period. A caller can choose period=twelve-months for the complete available trend window. Dates use the configured company timezone. The API accepts only the current or preceding eleven monthly starts. Page defaults to 1, pageSize to 100, maximum 1000.

The detail list is the dashboard's own governed drill-through. It does not promise Accounts bill-page access to Purchase users. No bill mutation permission is added. Permission page dashboards.purchase-spending initially grants view and the existing PO commercial flag to PURCHASE_MANAGER, TECHNICAL_DIRECTOR and MANAGING_DIRECTOR where their PO view is already allowed. The reader requires its own view and commercial grants, an active company/employee/assignment/role activation and effective operational scope. Department, warehouse, rack/bin and own-record scope are applied through the source PO; director cross-scope access must be explicitly enabled. Company or permission refusal is 403 DASHBOARD_ACCESS_DENIED. Invalid period, date or paging is 400 DASHBOARD_REQUEST_INVALID. Empty permitted data is represented by empty amount arrays, not a fabricated INR total.

One restricted SECURITY DEFINER SQL reader produces the calendar, permission decision, summaries and paged rows in one statement. Runtime gets EXECUTE, without SELECT on financial tables. Migration 20260914020000 guards the function's body, owner, search path and ACL. Installer provisioning reconciles the grant. Rollback refuses changed page permissions and does not remove financial records.
