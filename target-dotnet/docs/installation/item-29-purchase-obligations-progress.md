# Item 29 purchase obligations: GRNI and vendor advances

Status: implemented and verified in Release. The migration fact passes, and the corrected full nine-stage runtime fact passes. Matching Debug checks also pass; this is not a full-suite or complete Item 29 claim.

The purchase obligations endpoint is GET /api/v1/dashboards/purchase/obligations. It returns two tiles, per-vendor native-currency totals and a filtered, paged source list. Filters: queue (grni or vendor-advances), vendorId, currency, documentId, page (default 1), pageSize (default 100, maximum 1000). Filters apply to the underlying list; the overview remains the full authorized scope.

GRNI counts distinct finalized normal, unreversed GRNs with quantity not covered by accepted bills. Its value is unbilled quantity times the receipt unit-rate snapshot, in native PO currency. It is not gross bill payable, bank cash or final landed INR. Age uses the receipt date in the configured company timezone.

Vendor advances count active advances with a remaining balance. Value is recorded advance amount minus bill adjustments plus adjustment restorations. Reversed advances are excluded. Age starts at PaidDate. Advances remain visible after a PO is cancelled until governed financial operations settle or reverse them.

The private SQL function returns both projections in one statement and checks live company membership, employee status, role assignments/activation, page view/commercial permission and operational scope. The new page is dashboards.purchase-obligations, initially granted to eligible Purchase Manager, Technical Director and Managing Director roles from their existing PO view/commercial grants. It does not widen Accounts bill or payment mutation rights. Runtime gets EXECUTE, not direct financial-table SELECT. Installer provision and status include the new function authority.

A missing permission returns 403 DASHBOARD_ACCESS_DENIED. An invalid queue/page/currency returns 400 DASHBOARD_REQUEST_INVALID. Inconsistent negative receipt or advance balances return 409 DASHBOARD_SOURCE_INCONSISTENT with administrator action required. Permitted empty results return zero counts and empty currency arrays.

The frontend must use the endpoint's filtered list for drill-down. Source IDs identify the GRN line or advance, its historical PO version and root, vendor and item where applicable. Other pages retain their own access checks.
