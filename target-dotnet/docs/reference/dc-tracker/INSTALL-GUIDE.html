Upgrade from Rev 1 to Rev 2 (you already installed Rev 1)

Using the Rev 2 features

  • Company selector (top bar): "Both companies", SESS PVT LTD or SESS (Proprietorship). The dashboard, register, billing, reports and exports follow it. The dashboard also shows a company-wise table.
  • New DC: choose the Company first. The number series follows it (RDC/SPVT/220/26-27 or RDC/SESS/001/26-27), and the print shows that company's GSTIN, PAN, CIN and address. A proprietorship DC prints "Proprietor: Paramanantham Alagueaswari".
  • Print DC:
    • Tick the copies you want: Original for Consignee, Duplicate for Transporter, Triplicate for Consignor.
    • Edit the Terms & Conditions box if needed, then click Update preview, then Print.
    • Edited terms are saved on that DC and logged in its history. Only Store, Purchase and Admin can edit them.
    • The default terms follow Rule 55 of the CGST Rules 2017 and Section 143 (job work: inputs back within 1 year, capital goods within 3 years). Please have your auditor or CA review the wording once.
  • Bulk Import / Export (menu → Masters & data):
    1. Download template. It's also in the zip as DC-Tracker-Import-Template.xlsx.
    2. Fill DC_Lines with one row per item; rows with the same Company + DC Type + DC No form one DC. Parties and Items are optional. The Instructions sheet has examples, and Lists has valid company codes, employee login IDs, categories and units.
    3. Upload → Validate. Errors are listed with the Excel row number. Fix them in Excel and validate again.
    4. Click Import once the file shows "valid". Nothing is saved while any error exists. DC counters move past the imported numbers automatically.
    Export to Excel gives existing DCs in the same format, for backup, or to correct in Excel and re-import into a new setup.

2. Install on your Google Drive (admin, one time)

  1. On a computer, open drive.google.com and sign in with the company account.
  2. Create the database from the Excel file in the zip (recommended):
    1. In Drive, click New → File upload and choose DC-Tracker-Database-Rev1.xlsx.
    2. Double-click the uploaded file, then click File → Save as Google Sheets. A Google Sheet copy opens.
    3. Rename it DC Tracker – Database.
    It already contains all 303 DCs from your old register (196 RDC and 107 NRDC, 832 item lines) and 145 parties, converted to the app format, so you don't need to run importLegacy (section 8).
    To start with an empty database instead, create a Blank spreadsheet.
  3. In the sheet menu, click Extensions → Apps Script. The script editor opens in a new tab. Rename the project (top left, "Untitled project") to DC Tracker.
  4. Code.gs: click Code.gs on the left, select all (Ctrl+A), delete, then paste the full content of Code.gs from the zip. Open the file from the zip with Notepad and use Ctrl+A, Ctrl+C.
  5. Other scripts: click + next to "Files" → Script, type Reports, press Enter, delete the sample code and paste Reports.gs. Repeat for Jobs and Print.
  6. HTML files: click + → HTML, type Index, delete the sample and paste Index.html. Repeat for Css and App.
  7. Manifest: click the gear icon (Project Settings) on the left, tick "Show 'appsscript.json' manifest file in editor". Go back to the editor (<> icon), open appsscript.json, replace its content with the one from the zip.
  8. Click the Save icon (or Ctrl+S). No red error bar should appear.
  9. In the toolbar function dropdown, select setup and click Run.
  10. Google asks for permission. Click Review permissions → choose the company account → you may see "Google hasn't verified this app". This is normal for your own script. Click Advanced → Go to DC Tracker (unsafe) → Allow.
    Permissions requested: edit this spreadsheet, create files in your Drive (scan folders and PDFs), send e-mail as you (reminders), and run a daily trigger. Your data stays in your own Drive.
  11. Wait about 30–60 seconds. The Execution log at the bottom shows "Setup complete" with links to the database and the Drive folder DC Tracker – Documents. Your spreadsheet now has tabs such as DC, DCItems, Users and Settings.

3. Publish the app and get the link

  1. In the script editor click Deploy → New deployment.
  2. Click the gear next to "Select type" → Web app.
  3. Description: Rev 1. Execute as: Me. Who has access: Anyone.
  4. Click Deploy and approve again if asked. Copy the Web app URL. It looks like https://script.google.com/macros/s/AKfy…/exec.
  5. Share this one link with all employees on WhatsApp or e-mail. It works on laptop and mobile.
Why "Anyone"? Engineers don't need a Google account. They sign in with the app's own Login ID + password, and each person sees only what their role allows.
Google Workspace accounts: if "Anyone" is not offered, your Workspace admin has restricted it. Choose "Anyone within your company". Every user then also needs a company Google login on their phone.

4. First admin login & settings

  1. Open the Web app URL. Login ID admin, password <REDACTED>.
  2. You are asked to set a new password immediately. Keep it safe.
  3. Go to Settings and check:
    • Company name, address, GSTIN, CIN, PAN (these print on the DC)
    • STORE_EMAIL, ACCOUNTS_EMAIL, PURCHASE_EMAIL, ADMIN_EMAIL: optional extra addresses for the daily e-mails. Users with an e-mail in their login already receive their role's digest automatically.
    • RDC_DEFAULT_DUE_DAYS (15), NRDC_BILL_REMIND_DAYS (3), ESCALATE_AFTER_DAYS (7)
    • DC number counters: RDC|26-27 = 219 means the next RDC is RDC/SPVT/220/26-27. Set these to the last number used in Tally before you start.
    Click Save settings.
  4. Go to Parties & Items and add your regular customers and frequently sent items. The DC form then fills in address, GSTIN, HSN, unit and category.
  5. Create a test DC (+ New DC). Check the print preview matches your Tally format, then cancel it (Cancel DC with reason "test").

Admin: add or edit a user

  1. Log in as admin → Users & Logins → + Add user, or click an existing user.
  2. Enter Full name, Login ID (e.g. k.kumar), Role, E-mail (for reminders), Mobile, Reporting manager e-mail (overdue escalation), and an initial password (min 6 characters).
  3. Save. Give the user the app link, their Login ID and the initial password. They must change it at first login.
  4. For employees, set the Reporting manager e-mail to the Service Manager or Production Manager.
  5. To remove someone who left: set Active = NO. Their DC history is kept for audit.

Forgot password

The user asks the admin. Admin → Users & Logins → click the user → type a new password in "Reset password" → Save. The user must change it again at next login. After 5 wrong passwords the login locks for 15 minutes.

User: first login

  1. Open the app link → enter Login ID and password (<REDACTED>) → Sign in.
  2. Screen "Set your own password": enter the current password, then the new password twice → Save password.
  3. Sessions last 6 hours of inactivity. After that, sign in again.

6. Use on mobile phone

The app adapts to phone screens. The menu is under the ☰ button at top left, and your name, Change password and Sign out are at the bottom of that menu.

Android (Chrome)

  1. Open the app link in Chrome.
  2. Tap ⋮ (top right) → Add to Home screen → Add.
  3. A "DC Tracker" icon appears on the home screen. Open it like an app.

iPhone (Safari)

  1. Open the app link in Safari.
  2. Tap the Share icon → Add to Home Screen → Add.
  3. Open DC Tracker from the home screen.

Upload a signed DC from the phone camera

  1. Open My DCs → tap the DC → Upload signed copy / proof.
  2. Choose document type (Customer signed DC copy, Gate entry, End-user acknowledgement…).
  3. Tap the file box → Camera → take a clear photo of the full DC → it is compressed automatically.
  4. Enter gate entry no, date and end-user name → Upload. The file is saved in that DC's Drive folder.
A grey line at the top saying "This application was created by another user, not by Google" is normal for Apps Script apps.

7. Daily use by role

Store

  1. + New DC → choose RDC / NRDC / Warranty → party, material taken by (employee), purpose, due date (compulsory for RDC and Warranty), items with category → Create DC → Print. To use a DC number already made in Tally, type it in the DC No box.
  2. Every morning open Store Desk:
    • accept or reject returns employees submitted (check the material physically)
    • confirm hardcopies received
    • approve extension requests
  3. When an employee returns material at the counter, store can record it directly with Return / consumption on the DC. It is verified immediately.

Engineer (material taken on DC)

  1. My DCs shows every open DC in your name.
  2. After delivery: Upload signed copy / proof (customer signature, gate entry, end user).
  3. When material comes back: Return / consumption. Enter qty returned to store, consumed at site, and lost/damaged → Submit to store. You get an Acknowledgement No (print or screenshot it). This is your proof of submission.
  4. Give the signed hardcopy to store → tap I handed over hardcopy with the date.
  5. If the customer needs the material longer: Request extension with the reason, before the due date.

Purchase

+ New DC for material going to suppliers, job workers (RDC, purpose JOB WORK) or warranty vendors (Warranty DC with vendor, RMA and serial no). Follow up with the vendor. When material comes back, record it with Return / consumption, and store verifies it on receipt. The daily e-mail lists overdue warranty and job-work DCs.

Service Manager / Production Manager

Dashboard → Employee accountability shows who in the team is holding material. Approvals is where you approve or reject extension requests. The morning e-mail lists your team's overdue DCs.

MD / TD

Dashboard for the company-wide position, ISO Audit Report, Audit Log, and Approvals for extension requests. The morning management summary names the employees with the most overdue DCs.

Accounts

Billing (awaiting invoice) → enter invoice no and date → Save. A non-returnable DC closes automatically. Use Not billable with a reason for FOC, warranty replacement or samples.

Management / QA

Dashboard for the live position and the employee accountability table. ISO Audit Report → choose period → Print report for audits.

When does a DC close?
RDC / Warranty: all qty returned/consumed/accounted and hardcopy received by store (and invoice, if chargeable).
NRDC: as soon as the invoice number is entered.

8. Import the old Excel register (optional)

Skip this section if you created the database from DC-Tracker-Database-Rev1.xlsx in step 2. Your register data is already inside. Use the steps below only if you started from a blank sheet.
  1. Upload DC REGISTER SPVT 2026-2027 (OR_OP6_5).xlsx to Google Drive.
  2. Open it → File → Save as Google Sheets. A new Google Sheet copy opens.
  3. Copy its ID from the address bar: the part between /d/ and /edit.
  4. In the app: Settings → paste into LEGACY_SHEET_ID → Save.
  5. In the script editor select importLegacy → Run. The log shows e.g. "RDC: imported 196 DCs (450 item lines)".
  6. On the Dashboard, fix the red "Returnable without due date" DCs. In the old register these had =TODAY() as the due date. Also assign DCs listed under "(not assigned)".
Run the import before you start creating new DCs in the app, and set the counters (section 4) so new numbers continue after the last Tally number. Running the import twice is safe, because already-imported DCs are skipped.

9. Updating to a new revision

  1. Open the database sheet → Extensions → Apps Script.
  2. Replace the content of the changed files with the new revision (same names).
  3. Save → Deploy → Manage deployments → pencil ✏ icon → Version: New version → Description Rev 2 → Deploy.
  4. The link stays the same. Users just refresh. Your data is not touched.
Backup: once a month, open the database sheet and use File → Make a copy, or File → Download → Microsoft Excel (.xlsx) to get an offline Excel backup. Scans and PDFs are already in the Drive folder DC Tracker – Documents.
